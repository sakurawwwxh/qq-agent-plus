# 模型替换链（本地定制功能）

位置：设置 → 模型 API，在“模型 API”和“兜底模型”之间。

## 行为

- 聊天、语音转文字、TTS、图片生成各一条链，分别启用，互不消耗位置。
- 默认三个空选择框，可留空、清空，点击＋添加（每条最多 64 框）。空框跳过。
- 选择器列出全部已登记的提供商/模型；媒体链额外列出对应服务预设。模型目录可能同时含聊天和媒体模型，请选择支持目标用途的模型。
- 原模型继续使用。仅该模型请求满足已保存的触发条件时才推进，不猜测错误文案，不响应网页/插件/图片下载错误。
- D 为当前模型、链为 A/B/C：D403 → A，A403 → B，B403 → C。切到 C 立即关闭该链，继续尝试 C；C 保留为当前模型，不循环、不恢复 D。
- 每次切换同步更新并原子保存当前提供商、地址、模型及对应凭据；重启保留进度。选择框不存密钥。
- 重新启用或修改选择顺序，从第一个有效选择重新开始。关闭保留条目。
- 多个旧请求同时触发替换，只消费一次位置。用户在页面编辑期间后台推进时，旧页面保存返回 409，防止把当前模型改回旧值。
- 主模型链先于原有兜底处理已选的错误条件；其他失败沿用原有重试/兜底。调用者明确指定专用模型 overrides 时，不推进全局主模型链。

## 自动替换触发条件

只显示一份触发条件模块，用下拉框选择主模型、ASR、TTS 或图片生成，四条链分别保存规则。

- 默认开启 HTTP 402、HTTP 403、明确额度耗尽的 HTTP 429；HTTP 401 默认关闭。
- 429 只识别 JSON 响应 `error.code` / `error.type`（也支持顶层 code/type）的精确标识：
  `insufficient_quota`、`insufficient_balance`、`insufficient_credits`、`billing_hard_limit_reached`。
- 普通 429、模糊的 `quota_exceeded`、错误文字提及额度、超时和 5xx 不消耗链位置，保留原重试/兜底。
- 只有真实的模型请求 HTTP 错误能触发。成功响应内的业务错误不被当作 HTTP 402/403/429。
- “保存此链触发条件”只保存下拉框所选链的规则，不保存列表、开关、其他链或普通设置，也不重置进度。
- 切换下拉框保留各链未保存的规则草稿；模块独立保存、重新读取和冲突提示。主“保存设置”不影响它。
- 修改规则会更新本链版本号，后台旧请求及旧页面不能覆盖新规则；未修改保存不增加版本号。
- 旧配置缺少规则时补齐上述默认值，保留原有条目、启用状态、游标和切换记录。

## 独立保存

四条链各有自己的蓝色保存按钮，页面底部“保存设置”不写入替换链。未修改直接保存不会重置进度；“重新读取此链”只刷新该链。详见 [模型替换链独立保存](MODEL_REPLACEMENT_SAVE.md)。

## 媒体与计费安全

- ASR 按片处理，仅重试失败片段，不重跑已经成功的片段。
- TTS 仅重试合成，不重发 QQ 语音。优先使用目标服务保存的音色，否则使用目标模型默认音色；无有效音色时拒绝启用。自建服务的音色按“地址＋模型”分别保存，不借用另一自建服务的音色。
- 图片链仅处理“创建生成请求”被已选错误条件明确拒绝。ModelScope 任务已创建后，轮询、下载失败不换模型、不再创建计费任务；网络超时和未知结果也不触发链。
- 原有额度、时间窗口、发送保护保持不变；插件、协议端和操作系统没有新增常驻进程。
- 403 也可能意味着权限或策略限制，并不必然是额度耗尽。本功能按已选 HTTP 状态及精确的额度错误码执行。
- 原有媒体凭据归属规则仍生效：不同域名不能借用上一家密钥。启用时会检查目标是否存在及必要凭据是否保存。

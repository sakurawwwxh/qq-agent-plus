# B 站插件

官方插件，`examples/plugins/bilibili`，apiVersion 2。范围是**读 + 观看 + 互动**；不做投稿、发动态。

## 快速开始：聊天里扫码登录

对机器人说「登录B站」（**仅管理员私聊**）→ 它在私聊发一张二维码（半块字符渲染，不经过第三方）→ 手机 B 站 App
扫码并在手机上确认 → 再说「好了」。群聊里不允许发起扫码登录：二维码会被任意群成员扫走并绑成
机器人的账号。登录成功后会在本机实测一次 `nav`，确认有效才报成功；
响应里缺 `bili_jct`（写操作必需）会直接报错、不保存半套凭据。登录链接过长、二维码放不进一条消息时，
插件会提示改用**控制台 → 插件 → B 站 → 扫码登录**（控制台用本地 SVG 渲染，不受消息长度限制）。
Cookie 由宿主加密保存、立即生效；控制台插件设置里手动粘 Cookie 的老办法仍可用；
`login status/logout` 随时查/退。**聊天内扫码登录/退出只允许管理员**（私聊或控制台）；群聊、非管理员私聊都会被拒，扫码结果也只认发起登录的会话。

只读操作有 `SESSDATA` 就够；写操作（点赞/投币/收藏/关注/评论/弹幕）还需要 `bili_jct`。

## 能做什么

| 工具 | 作用 | 需要登录 |
| --- | --- | --- |
| `search` | 搜索视频（标题、BV 号、UP 主、播放量、时长） | 否 |
| `video` | 视频详情、分 P、统计、评论、字幕语言 | 否（字幕正文需要） |
| `user` | UP 主资料、**直播状态**与最近投稿 | 否 |
| `popular` | 综合热门 / 排行榜 | 否 |
| `account` | `whoami`（当前账号/主人绑定）、`doctor` 自检、`notifications`（未读回复/@/赞）、历史、收藏夹、关注列表 | 是（只需 `SESSDATA`） |
| `read` | 两段式看懂视频：字幕全文（无字幕走宿主语音转写）＋弹幕密度采样＋热评楼中楼；需要画面时传 `frames:["02:31"]` 抽帧并转成文字描述 | 否 |
| `login` | 聊天内扫码登录 / 查登录态 / 退出 | 否 |
| `watch` | 取 DASH 音视频，宿主合流 mp4，按设置发到当前群 | 否（高清需要） |
| `interact` | 点赞 / 投币 / 收藏 / 关注（可取消）/ **一键三连**（点赞+投币 1 枚+收藏到默认收藏夹，已做过的自动跳过） | 是 |
| `comment` | 发评论；传 `rpid` 时内联回复那条具体评论（`root` 用于楼中楼），`timestamps:true` 把正文里的 `mm:ss` 换成可跳转时间戳链接 | 是 |
| `danmaku` | 读弹幕；发弹幕用 `danmaku_send` | 否 |

只读视频工具（`video` / `read` / `watch` / `danmaku`）除裸 BV 号、av 号外，也接受
`bilibili.com/video/...` 链接和 `b23.tv` 分享短链。短链只经宿主 HTTP 能力跟随，
插件会从最终页的 canonical 链接重新校验视频地址；不会展开任意网页。链接里的 `?p=N`
只用于识别视频号，不会自动切换分 P；要看指定分 P 仍在 `watch` 里显式传 `page`。
写操作仍要求裸 BV 号或 av 号，便于宿主把批准绑定到明确的视频目标。

## 配置

安装后在插件详情页的「插件设置」里填：

- **账号**：`SESSDATA`、`bili_jct`（CSRF，写操作必须）、可选 `buvid3`、`DedeUserID`（收藏夹/历史/关注需要）。
  浏览器登录 B 站 → 开发者工具 → Application → Cookies 复制。凭据由宿主加密保存，页面只显示"已配置"。
- **主人 UID（`ownerMid`，可选）**：填了就只允许这个 B 站账号写入。每次点赞/投币/收藏/关注/评论/弹幕前，
  插件会用 `nav` 接口核对**平台实际登录的 mid**（不信任 Cookie 里的 DedeUserID），不一致直接拒绝并说明
  当前登录的是谁；账号被换掉、凭据串号时不会拿别人的账号去写。`account what=whoami` 或「检测登录」
  会显示当前 UID 与绑定是否一致。留空 = 不限制（仍受管理员批准与每日配额约束）。
- **观看与发送**：默认清晰度（未登录一般只能取到 480P）、是否允许把视频发到群里（默认关）、单文件上限（5-80MB）。
- **读内容偏好**：每次读评论 / 弹幕的条数。

## 写操作：先批准，再计数

点赞、投币、收藏、关注、评论、发弹幕都属于写操作：

1. 详情页「需要批准的动作」里点「批准一次」或「批准 10 次」，默认 10 分钟内有效；
2. 插件每次写操作消费一次批准；过期或次数用完会直接失败，不自动重试；
3. 当天还有配额（互动 30、评论 10、弹幕 20），宿主按插件 + 动作 + 日期计数，跨天归零；
4. 每次调用都会在宿主日志里留一行（`[plugin:bilibili] POST api.bilibili.com...`）。

没有批准时，模型收到的是一句可读原因，不是静默失败。

## 观看视频

`watch` 走 `cap.media.download` 下载 DASH 视频与音频，再由宿主 `ffmpeg -c copy` 合流：

- 需要服务器装 `ffmpeg`/`ffprobe`（巡检的 media-tools 一项会显示）；
- 清晰度越高文件越大，默认上限 60MB；超限换更低清晰度；
- 只有**群聊**且设置里打开了「允许把视频发到群里」才会发文件；私聊/关闭时只返回标题、时长、链接；
- 文件保留在 `data/plugin-data/bilibili/media/`，只保留最近 5 个。

## 边界与已知限制

- 不支持番剧/付费内容/地区限制视频（DASH 流拿不到）；
- 被 B 站风控（-352）时返回可读错误，不会自动重试；
- 弹幕读取依赖 `x/v1/dm/list.so` 返回 XML；如果上游改成压缩/二进制，会明确报"没读到弹幕"而不是编内容；
- Cookie 会过期：写操作报 `账号未登录` 时重新复制一次即可；
- 不做自动投稿、自动发动态；三连也要管理员先批准（一次批准覆盖点赞+投币1枚+收藏）。


## 与 DSH B 站插件的差异（2026-10 评估存档）

**2026-10-24 补齐**（对照 humanism / dsh-bilibili 复查后）：主人 UID 绑定（`nav.mid` 核对，写操作前
不一致直接拒绝）、一键三连（一次批准，三步各自幂等并回读）、UP 主直播状态、`whoami` 自检。
仍未做且有意保留差异：手账/人格学习、每日自动取稿、本地 ASR 引擎、场景检测自动选帧、
收藏夹增删/自建。

对照 CZX2244/dsh-bilibili（提取向）逐项评估后的取舍。**有意不做**的项及理由：

- **必剪 ASR 兜底**：依赖 B 站匿名风控面（上游自己承认会被限流）。本项目 read 走宿主已配置的
  语音识别（无字幕视频照常出文稿），第三方用户未配置时会收到明确报错引导——确定性优先于零配置。
- **本地 ASR/视觉引擎**（sherpa-onnx / whisper.cpp / Ollama）：部署级运维负担，宿主已有的
  openai 兼容转写与视觉模型覆盖同一需求。
- **场景检测自动选帧**（scene/blurdetect）：DSH 用它给"模型没走两段式"兜底；本项目主路径
  就是模型驱动（读文稿→弹幕密度→自选时间点抽帧），模型能力足够时是重复机制。

**已对齐**的项：嵌套回跳 URL 凭据解析（登录）、need_login_subtitle 精确区分、
读路径两级风控退避（2.5s/5s）、弹幕密度采样、热评楼中楼。

**本项目独有**：视频合流发群、宿主沙箱/凭据加密/对象级批准/配额、多分 P、
写操作全链路审计、插件级 http 域名白名单。

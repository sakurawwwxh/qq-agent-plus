# 群管理动作

这四个工具只在**全局管理员在群里明确要求**时执行；模型主动唤醒或自己发挥时调用会被拒绝。
控制台「设置 → 平台 → 群管理」可以整体关闭这四个工具（关闭后模型看不到它们）。

- `set_group_ban`：禁言/解禁（`minutes`，0 = 解禁，最长 30 天）；
- `kick_group_member`：移出群（可选拒绝再次加群）；
- `recall_message`：撤回一条消息；
- `set_group_admin`：设置/取消群管理员。

规则：

1. `admin.ownerUin` 必须已配置，且本轮触发消息里确实有管理员本人的发言；没有就拒绝。
2. 不能对自己（机器人）或管理员执行禁言/踢人/设管理员。
3. 工具失败按发送类错误收口，预期内的拒绝不记异常面板；真正的协议端错误照常记录。
4. 这些工具不会自动触发，也不会因为"群里有人刷屏"就自行处理；需要管理员在群里说清楚。

没有配置管理员时，工具仍然会出现在工具表里，但调用一律返回“未配置全局管理员”。如果不想让模型看到这些工具，可以在角色卡/管理员附加规则里明确“不要使用群管理工具”，或直接不配置管理员（此时也没有好友审批/异常告警的私聊通道）。

## 主动禁言（实验，默认关闭）

`mute_member` 是另一条通道：不是管理员命令，而是模型觉得被本轮群友冒犯时的表达。它**默认关闭**，
即使开启也默认 dry-run（只记录“本来会禁言谁”，不调用协议端）。

硬边界：

- 只能在群聊使用，目标必须是**这一轮触发消息的发送者**；
- 目标必须是普通成员，群主、管理员、主人、机器人自己一律拒绝；
- 单次时长、同一人冷却、每群每日次数都有上限，越界拒绝而不是截断；
- 只能解除机器人自己下过的禁言，且不能撤销人类管理员的加罚；
- 每次调用（含拒绝）都写 `[mute]` 日志；禁言调用进副作用账本，结果未知时不会自动重试。

控制台入口：设置 → 对话与人格 → 主动禁言。可调总开关、dry-run、单次最长、同人冷却、每群每日次数。
冷却与每日次数保存在 `data/mute-state.json`，重启不会重置。
